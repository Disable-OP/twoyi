    12→//! Binder virtualisation skeleton — per-VM `/vm%d/dev/binder` Unix socket
    13→//! plus a userspace proxy that forwards binder transactions between the
    14→//! guest and the host's real `/dev/binder` driver.
    15→//!
    16→//! # What this mirrors
    17→//!
    18→//! Virtual Master's `libvm.so` (loaded into the Java app process) creates
    19→//! `/vm%d/dev/binder` via the `setupBinder()` JNI called from
    20→//! `com.android.vmcore.service.BinderService.m5206WWWWoWWWWo` (see
    21→//! `VM_JAVA_ANALYSIS.md` §5.2 and `GSI_BOOT_PLAN.md` §2.5 / §3.2). The
    22→//! guest's `servicemanager` then talks to this virtual binder instead of
    23→//! the host's `/dev/binder`, and the Java side wraps the host's
    24→//! `IActivityManager` with a `java.lang.reflect.Proxy` so servicemanager
    25→//! lookups for `activity` / `package` / `window` / etc. are re-routed
    26→//! back into the host app's `BinderService`.
    27→//!
    28→//! VM puts this in `libvm.so` (not `libkr64.so`) because binder is
    29→//! latency-sensitive and going through a separate process would add a
    30→//! context switch per transaction. Twoyi doesn't have a `libvm.so` yet,
    31→//! so for the skeleton we host the binder proxy inside the kr64 daemon
    32→//! process. A future task can split it out into a per-VM `libvm.so`
    33→//! analogue if the latency becomes a problem.
    34→//!
    35→//! # Skeleton status
    36→//!
    37→//! This is a **skeleton**: it compiles, has the right protocol constants,
    38→//! creates the device, accepts connections, and dispatches the standard
    39→//! ioctl set. What it does NOT do yet:
    40→//!
    41→//! * **Parcel parsing** for `SVC_MGR_GET_SERVICE` / `SVC_MGR_ADD_SERVICE`.
    42→//!   The guest sends a parcelled interface-descriptor + service-name
    43→//!   string; we'd need to follow the `binder_transaction_data.data.ptr`
    44→//!   pointer into the guest's write buffer to read it. The skeleton just
    45→//!   logs the request and returns `BR_FAILED_REPLY`.
    46→//! * **Handle translation.** When the guest does `BC_TRANSACTION` to
    47→//!   handle 5 (e.g. `activity`), we'd need to look up the *host's*
    48→//!   binder handle for `activity` (looked up earlier via
    49→//!   `SVC_MGR_GET_SERVICE` on the host's `/dev/binder`), patch the
    50→//!   transaction_data.target.handle, and forward via a real
    51→//!   `BINDER_WRITE_READ` ioctl on the host. The skeleton's
    52→//!   `forward_transaction_to_host` opens `/dev/binder` lazily and issues
    53→//!   the ioctl but does NOT yet translate handles or patch the offsets /
    54→//!   `flat_binder_object` array — that's the hard part and is left for
    55→//!   the next task (proposed: `BINDER-3`).
    56→//! * **Death notifications**, **BC_ACQUIRE_DONE** / **BC_INCREFS_DONE**
    57→//!   acknowledgements, **file-descriptor passing**, **async (one-way)
    58→//!   transactions**, **BC_TRANSACTION_SG** scatter-gather offsets. All
    59→//!   are accepted and logged but not actually processed.
    60→//!
    61→//! # Wire framing
    62→//!
    63→//! The guest's `libbinder.so` cannot call `ioctl()` on a Unix socket —
    64→//! `ioctl` on a `SOCK_STREAM` returns ENOTTY for binder ioctls. So
    65→//! either:
    66→//!
    67→//! 1. The guest's `libbinder.so` is patched (via LD_PRELOAD or a custom
    68→//!    `libc.so` shim) to translate `ioctl(fd, BINDER_*, arg)` calls into
    69→//!    framed socket messages on `/dev/binder`. This is what VM does
    70→//!    (the patching happens in `libvm.so` via shadowhook — see
    71→//!    `VM_KR64_ANALYSIS.md` §11), OR
    72→//! 2. The daemon creates `/dev/binder` as a real char device via
    73→//!    `mknodat(S_IFCHR, …)` and uses `binderfs` / a kernel module to
    74→//!    actually handle the ioctls. This is the "real driver" approach
    75→//!    and requires `CAP_MKNOD` + a per-VM binder context in the kernel.
    76→//!
    77→//! This skeleton uses approach (1). The wire format is documented in
    78→//! the [`Frame`] / [`Resp`] docs below. The guest-side patching code is
    79→//! a separate task (proposed: `BINDER-4`).
    80→//!
    81→//! # Module layout
    82→//!
    83→//! * [`create_binder_device`] — creates `{rootfs}/vm{id}/dev/binder` as
    84→//!   a Unix socket plus a `{rootfs}/dev/binder` symlink to it.
    85→//! * [`BinderProxy`] / [`BinderProxyHandle`] — owns the listener and
    86→//!   spawns the accept + worker threads.
    87→//! * [`ThreadPool`] — minimal fixed-size thread pool used by
    88→//!   `BinderProxy` for concurrent connection handling.
    89→//! * [`HandleTable`] — guest-handle ↔ host-handle ↔ service-name map.
    90→//! * `dispatch_request` / `handle_*` — per-ioctls handlers.
    91→//! * `servicemanager_proxy` / `forward_transaction_to_host` — the two
    92→//!   transaction dispatch paths (handle 0 → servicemanager, else → host).
    93→//! * Protocol constants (`BINDER_*`, `BC_*`, `BR_*`, `SVC_MGR_*`) —
    94→//!   exact matches of the kernel `<uapi/linux/android/binder.h>` and
    95→//!   AOSP `frameworks/native/libs/binder/IServiceManager.cpp`.

   115→// ============================================================================
   116→// ioctl number macros — identical to Linux <asm-generic/ioctl.h>.
   117→//
   118→// All binder ioctls use type 'b' (0x62). The ioctl number encodes the
   119→// direction (_IOC_NONE/_IOC_WRITE/_IOC_READ), the type, the nr, and the
   120→// argument size in a single u32. We compute these at compile time so
   121→// they can be `const` and used in match arms.
   122→// ============================================================================
   123→
   124→const _IOC_NONE: u32 = 0;
   125→const _IOC_WRITE: u32 = 1;
   126→const _IOC_READ: u32 = 2;
   127→
   128→#[inline]
   129→#[allow(non_snake_case)]
   130→const fn _IOC(dir: u32, type_: u32, nr: u32, size: u32) -> u32 {
   131→    (dir << 30) | (size << 16) | (type_ << 8) | nr
   132→}
   133→
   134→#[inline]
   135→#[allow(non_snake_case)]
   136→const fn _IO(t: u32, nr: u32) -> u32 {
   137→    _IOC(_IOC_NONE, t, nr, 0)
   138→}
   139→
   140→#[inline]
   141→#[allow(non_snake_case)]
   142→const fn _IOR(t: u32, nr: u32, size: u32) -> u32 {
   143→    _IOC(_IOC_READ, t, nr, size)
   144→}
   145→
   146→#[inline]
   147→#[allow(non_snake_case)]
   148→const fn _IOW(t: u32, nr: u32, size: u32) -> u32 {
   149→    _IOC(_IOC_WRITE, t, nr, size)
   150→}

   152→#[inline]
   153→#[allow(non_snake_case)]
   154→const fn _IOWR(t: u32, nr: u32, size: u32) -> u32 {

   239→/// `struct binder_transaction_data` — payload of `BC_TRANSACTION`,
   240→/// `BC_REPLY`, `BC_TRANSACTION_SG`, `BC_REPLY_SG`, and the corresponding
   241→/// `BR_TRANSACTION` / `BR_REPLY`.
   242→///
   243→/// The kernel struct has a union for `target` (4-byte `handle` OR 8-byte
   244→/// `ptr`) followed by an 8-byte `cookie`, totalling 16 bytes. We model
   245→/// that as `target_handle` (u32) + `target_pad` (u32) + `target_cookie`
   246→/// (u64), so the layout matches whether the sender used the handle form
   247→/// or the ptr form. The `data` union is similarly modelled as the larger
   248→/// `ptr` form (16 bytes).
   249→///
   250→/// Total: 64 bytes on aarch64 / x86_64, matching the kernel.
   251→#[repr(C)]
   252→#[derive(Clone, Copy, Default)]
   253→#[allow(dead_code)]
   254→pub struct BinderTransactionData {
   255→    pub target_handle: u32, // [ 0.. 4] — when target is a remote handle
   256→    pub target_pad:    u32, // [ 4.. 8] — padding (or low 4 bytes of ptr)
   257→    pub target_cookie: u64, // [ 8..16] — cookie (or high 4 bytes of ptr)
   258→    pub code:          u32, // [16..20] — transaction code (method id)
   259→    pub flags:         u32, // [20..24] — TF_* flags
   260→    pub sender_pid:    i32, // [24..28] — pid_t (signed)
   261→    pub sender_euid:   u32, // [28..32] — uid_t (unsigned)
   262→    pub data_size:     u64, // [32..40] — size of data buffer
   263→    pub offsets_size:  u64, // [40..48] — size of offsets array
   264→    pub data_ptr:      u64, // [48..56] — user pointer to data buffer
   265→    pub offsets_ptr:   u64, // [56..64] — user pointer to offsets array
   266→}

   634→// ============================================================================
   635→// Wire framing for the Unix-socket proxy protocol.
   636→//
   637→// The guest's libbinder.so is patched (or shimmed via LD_PRELOAD) to
   638→// translate `ioctl(fd, BINDER_*, arg)` calls into framed socket messages
   639→// on the per-VM /vm%d/dev/binder Unix socket. Each frame is:
   640→//
   641→//   [u32 cmd]      — the binder ioctl number (BINDER_WRITE_READ, …)
   642→//   [u32 arg_len]  — payload size in bytes (0 for _IO ioctls)
   643→//   [u32 arg_len bytes of payload]
   644→//
   645→// The server responds with:
   646→//
   647→//   [i32 ret]      — 0 on success, -errno on failure
   648→//   [u32 arg_len]  — response payload size in bytes
   649→//   [u32 arg_len bytes of payload]
   650→//
   651→// For `BINDER_WRITE_READ` specifically, the request payload is our own
   652→// [`WireBinderWriteRead`] (NOT the kernel struct, because the kernel
   653→// struct uses pointers that don't make sense over a socket), and the
   654→// response payload is [`WireBinderWriteReadResponse`].
   655→// ============================================================================
   656→
   657→/// A parsed request frame received from the guest.
   658→struct Frame {
   659→    /// The binder ioctl number (`BINDER_WRITE_READ`, `BINDER_VERSION`, …).
   660→    cmd: u32,
   661→    /// Variable-length payload (the ioctl's `arg` bytes).
   662→    payload: Vec<u8>,
   663→}
   664→
   665→/// A response frame sent back to the guest.
   666→struct Resp {
   667→    /// Return value: 0 on success, negative errno on failure.
   668→    ret: i32,
   669→    /// Variable-length response payload (the bytes the ioctl would have
   670→    /// written into `arg`).
   671→    payload: Vec<u8>,
   672→}
   673→
   674→/// Serialised `BINDER_WRITE_READ` request payload (our own wire format —
   675→/// NOT the kernel struct, because the kernel struct uses user pointers
   676→/// that don't make sense over a socket).
   677→///
   678→/// Layout: `[u32 write_size][u32 read_capacity][write_size bytes]`.
   679→#[derive(Default)]
   680→#[allow(dead_code)]
   681→struct WireBinderWriteRead {
   682→    /// The guest's outgoing BC_* command stream.
   683→    write_buffer: Vec<u8>,
   684→    /// Maximum bytes the guest is willing to receive in the read_buffer.
   685→    /// The server may return fewer.
   686→    read_capacity: u32,
   687→}
   688→
   689→/// Serialised `BINDER_WRITE_READ` response payload.
   690→///
   691→/// Layout: `[u32 read_size][read_size bytes]`.
   692→#[derive(Default)]
   693→#[allow(dead_code)]
   694→struct WireBinderWriteReadResponse {
   695→    /// The BR_* command stream the server wants the guest to consume.
   696→    read_buffer: Vec<u8>,
   697→}

   699→// ============================================================================
   700→// Service-manager handle table.
   701→// ============================================================================
   702→
   703→/// Per-VM handle table — maps guest-visible binder handles to host
   704→/// binder handles and to service names.
   705→///
   706→/// When the guest calls `SVC_MGR_GET_SERVICE("activity")`, the proxy:
   707→///   1. Looks up "activity" in `by_name` to find the guest handle.
   708→///   2. If not present, calls `SVC_MGR_GET_SERVICE("activity")` on the
   709→///      host's `/dev/binder` to get the host handle, allocates a new
   710→///      guest handle, and records both mappings.
   711→///   3. Returns the guest handle to the guest as a strong binder in the
   712→///      reply parcel.
   713→///
   714→/// Subsequent `BC_TRANSACTION` calls from the guest to that guest handle
   715→/// are translated: `target.handle` is rewritten from guest handle to
   716→/// host handle before forwarding to the host's `/dev/binder`.
   717→#[derive(Default)]
   718→pub struct HandleTable {
   719→    /// guest_handle → host_handle.
   720→    by_guest: HashMap<u32, u32>,
   721→    /// service_name → guest_handle.
   722→    by_name: HashMap<String, u32>,
   723→    /// Next guest handle to allocate (starts at 1; 0 is reserved for
   724→    /// the servicemanager itself).
   725→    next: u32,
   726→}
   727→
   728→impl HandleTable {
   729→    /// Create an empty handle table. Handle 0 is reserved for the
   730→    /// servicemanager; the first allocated handle is 1.
   731→    pub fn new() -> Self {
   732→        HandleTable {
   733→            by_guest: HashMap::new(),
   734→            by_name: HashMap::new(),
   735→            next: 1,
   736→        }
   737→    }
   738→
   739→    /// Allocate a new guest handle bound to `host_handle` and return it.
   740→    pub fn allocate(&mut self, host_handle: u32) -> u32 {
   741→        let g = self.next;
   742→        self.next += 1;
   743→        self.by_guest.insert(g, host_handle);
   744→        g
   745→    }
   746→
   747→    /// Record that service `name` is reachable via guest handle `g`.
   748→    pub fn register(&mut self, name: &str, guest_handle: u32) {
   749→        self.by_name.insert(name.to_string(), guest_handle);
   750→    }
   751→
   752→    /// Look up a guest handle by service name.
   753→    pub fn lookup_by_name(&self, name: &str) -> Option<u32> {
   754→        self.by_name.get(name).copied()
   755→    }
   756→
   757→    /// Translate a guest handle to the corresponding host handle.
   758→    pub fn lookup_host(&self, guest_handle: u32) -> Option<u32> {
   759→        self.by_guest.get(&guest_handle).copied()
   760→    }
   761→}

   763→// ============================================================================
   764→// Device creation.
   765→// ============================================================================
   766→
   767→/// Create the per-VM binder device.
   768→///
   769→/// * Creates `{rootfs}/vm{vm_id}/dev/binder` as a Unix-domain socket —
   770→///   this is the actual socket the guest connects to. (`rootfs` here is
   771→///   treated as the per-VM data directory; the guest's chroot rootfs is
   772→///   a sibling, not a parent.)
   773→/// * Creates `{rootfs}/dev/binder` as a symlink to
   774→///   `../vm{vm_id}/dev/binder` so the guest (chrooted into `rootfs`)
   775→///   sees the conventional `/dev/binder` path. The symlink target is
   776→///   relative so it resolves correctly inside the chroot.
   777→///
   778→/// The function binds the socket listener, sets mode 0666 on it (so the
   779→/// guest process — which may run as a different uid inside the chroot —
   780→/// can `connect()`), then drops the listener and returns the path. The
   781→/// caller is expected to immediately pass the path to
   782→/// [`BinderProxy::new`], which re-binds it. (The alternative — returning
   783→/// the listener itself — is awkward because `UnixListener` doesn't
   784→/// `Clone`, and we want `create_binder_device` to be callable
   785→/// independently of `BinderProxy`.)
   786→///
   787→/// # Errors
   788→///
   789→/// Returns an error if directory creation, `UnixListener::bind`, or
   790→/// `symlink` fails. Stale socket files / symlinks from a previous run
   791→/// are best-effort removed before bind (errors are logged but not
   792→/// propagated).
   793→pub fn create_binder_device(rootfs: &str, vm_id: u32) -> std::io::Result<String> {
   794→    let vm_dir = format!("{}/vm{}", rootfs, vm_id);
   795→    let vm_dev = format!("{}/dev", vm_dir);
   796→    let sock_path = format!("{}/dev/binder", vm_dir);
   797→    let link_path = format!("{}/dev/binder", rootfs);
   798→
   799→    // Make sure /vm{id}/dev and /dev exist.
   800→    fs::create_dir_all(&vm_dev)?;
   801→    fs::create_dir_all(format!("{}/dev", rootfs))?;
   802→
   803→    #[cfg(unix)]
   804→    {
   805→        let _ = fs::set_permissions(&vm_dev, fs::Permissions::from_mode(0o755));
   806→        let _ = fs::set_permissions(format!("{}/dev", rootfs), fs::Permissions::from_mode(0o755));
   807→    }
   808→
   809→    // Remove stale socket / symlink from a previous run.
   810→    match fs::remove_file(&sock_path) {
   811→        Ok(()) => info!("[KR64][binder] removed stale socket: {}", sock_path),
   812→        Err(e) if e.kind() == std::io::ErrorKind::NotFound => {}
   813→        Err(e) => warning!("[KR64][binder] could not remove {}: {}", sock_path, e),
   814→    }
   815→    match fs::remove_file(&link_path) {
   816→        Ok(()) => info!("[KR64][binder] removed stale symlink: {}", link_path),
   817→        Err(e) if e.kind() == std::io::ErrorKind::NotFound => {}
   818→        Err(e) => warning!("[KR64][binder] could not remove {}: {}", link_path, e),
   819→    }
   820→
   821→    // Bind the Unix listener. This creates the socket file as a side
   822→    // effect. (A production version would first `mknodat(S_IFSOCK|0666)`
   823→    // then `bind()` to it — matching VM's exact pattern at libkr64.so
   824→    // offset 0x11d770 — but `mknodat` requires CAP_MKNOD which is
   825→    // unavailable in many sandboxes. `UnixListener::bind` is the
   826→    // unprivileged fallback and works fine for the skeleton.)
   827→    let listener = UnixListener::bind(&sock_path)?;
   828→    #[cfg(unix)]
   829→    {
   830→        let _ = fs::set_permissions(&sock_path, fs::Permissions::from_mode(0o666));
   831→    }
   832→
   833→    // Create the symlink. Target is RELATIVE (`../vm{id}/dev/binder`)
   834→    // so the kernel resolves it relative to the symlink's own location
   835→    // — i.e. `{rootfs}/dev/` — which yields `{rootfs}/vm{id}/dev/binder`.
   836→    // This works inside the chroot too (no leading `/`).
   837→    #[cfg(unix)]
   838→    {
   839→        let target = format!("../vm{}/dev/binder", vm_id);
   840→        std::os::unix::fs::symlink(&target, &link_path)?;
   841→    }
   842→
   843→    info!(
   844→        "[KR64][binder] created socket {} (fd={}) and symlink {} → ../vm{}/dev/binder",
   845→        sock_path,
   846→        listener.as_raw_fd(),
   847→        link_path,
   848→        vm_id
   849→    );
   850→
   851→    // Drop the listener — the caller will re-bind via BinderProxy::new.
   852→    // We unlink the socket file so the re-bind doesn't hit EADDRINUSE.
   853→    drop(listener);
   854→    let _ = fs::remove_file(&sock_path);
   855→    Ok(sock_path)
   856→}

   858→// ============================================================================
   859→// Binder proxy — owns the listener + worker pool, accepts guest
   860→// connections, dispatches per-ioctl.
   861→// ============================================================================
   862→
   863→/// Owned binder proxy for one VM. Created via [`BinderProxy::new`],
   864→/// started via [`BinderProxy::spawn`] (which consumes self and returns a
   865→/// [`BinderProxyHandle`]).
   866→///
   867→/// The proxy owns:
   868→///   * The `UnixListener` bound to `{rootfs}/vm{id}/dev/binder`.
   869→///   * A lazily-opened file descriptor for the host's `/dev/binder`
   870→///     (opened on the first `BC_TRANSACTION` that needs forwarding).
   871→///   * A per-VM [`HandleTable`] (wrapped in `Arc<Mutex<…>>` so worker
   872→///     threads can share it).
   873→///   * A `shutdown` flag (atomic) used to ask the accept thread to exit.
   874→pub struct BinderProxy {
   875→    vm_id: u32,
   876→    listener: Option<UnixListener>,
   877→    path: String,
   878→    /// Opened lazily on the first `BC_TRANSACTION` that targets a
   879→    /// non-servicemanager handle. `None` means "not yet opened" (or
   880→    /// "open failed and we're returning errors for all forwards").
   881→    host_binder_fd: Arc<Mutex<Option<RawFd>>>,
   882→    /// Per-VM handle table (guest handle ↔ host handle ↔ service name).
   883→    handles: Arc<Mutex<HandleTable>>,
   884→    /// Set to true by [`BinderProxyHandle::shutdown`] / drop to ask the
   885→    /// accept thread to exit.
   886→    shutdown: Arc<AtomicBool>,
   887→}
   888→
   889→impl BinderProxy {
   890→    /// Construct a new binder proxy for `vm_id`, binding a Unix listener
   891→    /// to `socket_path` (which should be the path returned by
   892→    /// [`create_binder_device`]).
   893→    pub fn new(vm_id: u32, socket_path: &str) -> std::io::Result<Self> {
   894→        // Best-effort unlink of a stale socket from a previous run.
   895→        let _ = fs::remove_file(socket_path);
   896→
   897→        let listener = UnixListener::bind(socket_path)?;
   898→        #[cfg(unix)]
   899→        {
   900→            let _ = fs::set_permissions(socket_path, fs::Permissions::from_mode(0o666));
   901→        }
   902→
   903→        // Make the listening socket non-blocking so the accept thread
   904→        // can poll the shutdown flag between accept attempts.
   905→        let fd = listener.as_raw_fd();
   906→        let _ = unsafe { libc::fcntl(fd, libc::F_SETFL, libc::O_NONBLOCK) };
   907→
   908→        info!(
   909→            "[KR64][binder][vm{}] proxy bound to {} (fd={}, non-blocking)",
   910→            vm_id,
   911→            socket_path,
   912→            fd
   913→        );
   914→
   915→        Ok(BinderProxy {
   916→            vm_id,
   917→            listener: Some(listener),
   918→            path: socket_path.to_string(),
   919→            host_binder_fd: Arc::new(Mutex::new(None)),
   920→            handles: Arc::new(Mutex::new(HandleTable::new())),
   921→            shutdown: Arc::new(AtomicBool::new(false)),
   922→        })
   923→    }
   924→
   925→    /// Spawn the accept thread + worker pool, consuming self.
   926→    ///
   927→    /// Returns a [`BinderProxyHandle`] that holds the shutdown flag and
   928→    /// the accept-thread `JoinHandle`. When the handle is dropped, the
   929→    /// shutdown flag is set and the accept thread is joined.
   930→    pub fn spawn(mut self) -> std::io::Result<BinderProxyHandle> {
   931→        let listener = self
   932→            .listener
   933→            .take()
   934→            .expect("BinderProxy::spawn: listener already taken");
   935→        let host_fd = Arc::clone(&self.host_binder_fd);
   936→        let handles = Arc::clone(&self.handles);
   937→        // Clone the shutdown Arc twice: one for the accept thread, one
   938→        // for the returned handle. Both share the same AtomicBool.
   939→        let shutdown_for_thread = Arc::clone(&self.shutdown);
   940→        let shutdown_for_handle = Arc::clone(&self.shutdown);
   941→        let vm_id = self.vm_id;
   942→        let path = self.path.clone();
   943→
   944→        let accept_thread = thread::Builder::new()
   945→            .name(format!("kr64-binder-accept-{}", vm_id))
   946→            .spawn(move || {
   947→                // The pool lives inside the accept thread so its Drop
   948→                // (which joins workers) runs when the accept thread
   949→                // exits. This ensures workers are joined BEFORE the
   950→                // accept thread returns.
   951→                let pool = ThreadPool::new(BINDER_THREAD_POOL_SIZE);
   952→                info!(
   953→                    "[KR64][binder][vm{}] accept loop started (pool_size={})",
   954→                    vm_id, BINDER_THREAD_POOL_SIZE
   955→                );
   956→
   957→                while !shutdown_for_thread.load(Ordering::Acquire) {
   958→                    match listener.accept() {
   959→                        Ok((stream, _addr)) => {
   960→                            info!("[KR64][binder][vm{}] client connected", vm_id);
   961→                            let host_fd = Arc::clone(&host_fd);
   962→                            let handles = Arc::clone(&handles);
   963→                            pool.execute(move || {
   964→                                if let Err(e) =
   965→                                    handle_connection(stream, vm_id, &host_fd, &handles)
   966→                                {
   967→                                    warning!(
   968→                                        "[KR64][binder][vm{}] connection handler ended: {}",
   969→                                        vm_id, e
   970→                                    );
   971→                                }
   972→                            });
   973→                        }
   974→                        Err(e) if e.kind() == std::io::ErrorKind::WouldBlock => {
   975→                            // No pending connection — sleep briefly so
   976→                            // we don't burn CPU. The accept thread's
   977→                            // main job is to wait for the next
   978→                            // connection or for shutdown.
   979→                            std::thread::sleep(std::time::Duration::from_millis(25));
   980→                        }
   981→                        Err(e) => {
   982→                            warning!("[KR64][binder][vm{}] accept error: {}", vm_id, e);
   983→                            std::thread::sleep(std::time::Duration::from_millis(50));
   984→                        }
   985→                    }
   986→                }
   987→                info!("[KR64][binder][vm{}] accept loop exiting", vm_id);
   988→                // pool drops here → workers receive Terminate and join.
   989→            })?;
   990→
   991→        Ok(BinderProxyHandle {
   992→            shutdown: shutdown_for_handle,
   993→            accept_thread: Some(accept_thread),
   994→            path,
   995→        })
   996→    }
   997→}
   998→
   999→/// Handle to a running binder proxy. Dropping this sets the shutdown
  1000→/// flag and joins the accept thread.
  1001→pub struct BinderProxyHandle {
  1002→    shutdown: Arc<AtomicBool>,
  1003→    accept_thread: Option<JoinHandle<()>>,
  1004→    path: String,
  1005→}
  1006→
  1007→impl BinderProxyHandle {
  1008→    /// Ask the accept thread to shut down. (Does not join — that
  1009→    /// happens on drop.)
  1010→    pub fn shutdown(&self) {
  1011→        self.shutdown.store(true, Ordering::Release);
  1012→    }
  1013→
  1014→    /// The socket path the proxy is listening on.
  1015→    pub fn path(&self) -> &str {
  1016→        &self.path
  1017→    }
  1018→}
  1019→
  1020→impl Drop for BinderProxyHandle {
  1021→    fn drop(&mut self) {
  1022→        self.shutdown.store(true, Ordering::Release);
  1023→        if let Some(t) = self.accept_thread.take() {
  1024→            let _ = t.join();
  1025→        }
  1026→        // Best-effort unlink the socket file so a re-run of the daemon
  1027→        // doesn't fail with EADDRINUSE.
  1028→        let _ = fs::remove_file(&self.path);
  1029→    }
  1030→}

  1032→// ============================================================================
  1033→// Minimal thread pool — fixed-size, MPMC via std::sync::mpsc.
  1034→//
  1035→// We can't add `rayon` / `crossbeam` / etc. (the crate is std + libc
  1036→// only), so we roll our own. This is the classic Rust-book ThreadPool
  1037→// with a Terminate control message added for clean shutdown.
  1038→// ============================================================================
  1039→
  1040→type Job = Box<dyn FnOnce() + Send + 'static>;
  1041→
  1042→enum Message {
  1043→    Job(Job),
  1044→    Terminate,
  1045→}
  1046→
  1047→struct Worker {
  1048→    thread: Option<JoinHandle<()>>,
  1049→}
  1050→
  1051→impl Worker {
  1052→    fn new(receiver: Arc<Mutex<mpsc::Receiver<Message>>>) -> Self {
  1053→        let thread = thread::spawn(move || loop {
  1054→            let msg = receiver.lock().unwrap().recv();
  1055→            match msg {
  1056→                Ok(Message::Job(job)) => job(),
  1057→                Ok(Message::Terminate) | Err(_) => break,
  1058→            }
  1059→        });
  1060→        Worker {
  1061→            thread: Some(thread),
  1062→        }
  1063→    }
  1064→}
  1065→
  1066→/// A fixed-size thread pool. Used by [`BinderProxy`] to handle multiple
  1067→/// concurrent guest connections.
  1068→pub struct ThreadPool {
  1069→    workers: Vec<Worker>,
  1070→    sender: Option<mpsc::Sender<Message>>,
  1071→}
  1072→
  1073→impl ThreadPool {
  1074→    /// Create a pool with `size` worker threads. Panics if `size == 0`.
  1075→    pub fn new(size: usize) -> Self {
  1076→        assert!(size > 0, "ThreadPool::new: size must be > 0");
  1077→        let (sender, receiver) = mpsc::channel();
  1078→        let receiver = Arc::new(Mutex::new(receiver));
  1079→        let mut workers = Vec::with_capacity(size);
  1080→        for _ in 0..size {
  1081→            workers.push(Worker::new(Arc::clone(&receiver)));
  1082→        }
  1083→        ThreadPool {
  1084→            workers,
  1085→            sender: Some(sender),
  1086→        }
  1087→    }
  1088→
  1089→    /// Submit a job to the pool. If all workers are busy, the job is
  1090→    /// queued until one becomes free.
  1091→    pub fn execute<F>(&self, f: F)
  1092→    where
  1093→        F: FnOnce() + Send + 'static,
  1094→    {
  1095→        if let Some(s) = &self.sender {
  1096→            if s.send(Message::Job(Box::new(f))).is_err() {
  1097→                warning!("[KR64][binder] thread pool: sender closed, job dropped");
  1098→            }
  1099→        }
  1100→    }
  1101→}
  1102→
  1103→impl Drop for ThreadPool {
  1104→    fn drop(&mut self) {
  1105→        // Close the sender so workers' recv() returns Err and they exit.
  1106→        if let Some(s) = self.sender.take() {
  1107→            for _ in &self.workers {
  1108→                let _ = s.send(Message::Terminate);
  1109→            }
  1110→        }
  1111→        // Join each worker.
  1112→        for w in &mut self.workers {
  1113→            if let Some(t) = w.thread.take() {
  1114→                let _ = t.join();
  1115→            }
  1116→        }
  1117→    }
  1118→}
  1119→
  1120→// ============================================================================
  1121→// Per-connection handler.
  1122→// ============================================================================
  1123→
  1124→/// Handle one guest connection: read frames, dispatch, write responses.
  1125→/// Returns when the guest disconnects (EOF) or an unrecoverable I/O
  1126→/// error occurs.
  1127→fn handle_connection(
  1128→    mut stream: UnixStream,
  1129→    vm_id: u32,
  1130→    host_fd: &Arc<Mutex<Option<RawFd>>>,
  1131→    handles: &Arc<Mutex<HandleTable>>,
  1132→) -> io::Result<()> {
  1133→    info!("[KR64][binder][vm{}] handling new connection", vm_id);
  1134→    loop {
  1135→        let req = match read_frame(&mut stream) {
  1136→            Ok(r) => r,
  1137→            Err(e) if e.kind() == io::ErrorKind::UnexpectedEof => {
  1138→                info!("[KR64][binder][vm{}] client disconnected", vm_id);
  1139→                return Ok(());
  1140→            }
  1141→            Err(e) => return Err(e),
  1142→        };
  1143→        let resp = dispatch_request(&req, vm_id, host_fd, handles);
  1144→        write_frame(&mut stream, &resp)?;
  1145→    }
  1146→}
  1147→
  1148→// ============================================================================
  1149→// Ioctl dispatcher.
  1150→// ============================================================================
  1151→
  1152→/// Dispatch one parsed request frame to the appropriate handler.
  1153→fn dispatch_request(
  1154→    req: &Frame,
  1155→    vm_id: u32,
  1156→    host_fd: &Arc<Mutex<Option<RawFd>>>,
  1157→    handles: &Arc<Mutex<HandleTable>>,
  1158→) -> Resp {
  1159→    match req.cmd {
  1160→        BINDER_VERSION => handle_version(vm_id),
  1161→
  1162→        BINDER_SET_MAX_THREADS => {
  1163→            let n = if req.payload.len() >= 4 {
  1164→                u32::from_ne_bytes(req.payload[0..4].try_into().unwrap_or([0; 4]))
  1165→            } else {
  1166→                0
  1167→            };
  1168→            info!(
  1169→                "[KR64][binder][vm{}] SET_MAX_THREADS = {} (acknowledged)",
  1170→                vm_id, n
  1171→            );
  1172→            Resp {
  1173→                ret: 0,
  1174→                payload: Vec::new(),
  1175→            }
  1176→        }
  1177→
  1178→        BINDER_SET_CONTEXT_MGR => {
  1179→            info!(
  1180→                "[KR64][binder][vm{}] SET_CONTEXT_MGR — guest is now the servicemanager",
  1181→                vm_id
  1182→            );
  1183→            // Accept: the guest's servicemanager has registered with us.
  1184→            // We do NOT proxy this to the host — the host already has
  1185→            // its own servicemanager on /dev/binder.
  1186→            Resp {
  1187→                ret: 0,
  1188→                payload: Vec::new(),
  1189→            }
  1190→        }
  1191→
  1192→        BINDER_THREAD_EXIT => {
  1193→            info!("[KR64][binder][vm{}] THREAD_EXIT", vm_id);
  1194→            Resp {
  1195→                ret: 0,
  1196→                payload: Vec::new(),
  1197→            }
  1198→        }
  1199→
  1200→        BINDER_WRITE_READ => handle_write_read(&req.payload, vm_id, host_fd, handles),
  1201→
  1202→        other => {
  1203→            warning!(
  1204→                "[KR64][binder][vm{}] unknown ioctl 0x{:08x} ({} bytes payload)",
  1205→                vm_id,
  1206→                other,
  1207→                req.payload.len()
  1208→            );
  1209→            Resp {
  1210→                ret: -(libc::EINVAL as i32),
  1211→                payload: Vec::new(),
  1212→            }
  1213→        }
  1214→    }
  1215→}
  1216→
  1217→/// `BINDER_VERSION` handler — return the protocol version.
  1218→fn handle_version(vm_id: u32) -> Resp {
  1219→    info!(
  1220→        "[KR64][binder][vm{}] VERSION → {}",
  1221→        vm_id, BINDER_CURRENT_PROTOCOL_VERSION
  1222→    );
  1223→    Resp {
  1224→        ret: 0,
  1225→        payload: BINDER_CURRENT_PROTOCOL_VERSION.to_ne_bytes().to_vec(),
  1226→    }
  1227→}
  1228→
  1229→// ============================================================================
  1230→// BINDER_WRITE_READ handler — the workhorse.
  1231→// ============================================================================
  1232→
  1233→/// Handle a `BINDER_WRITE_READ` request.
  1234→///
  1235→/// The wire payload is [`WireBinderWriteRead`]: `[u32 write_size]
  1236→/// [u32 read_capacity][write_size bytes]`. We parse the write_buffer
  1237→/// into individual BC_* commands, dispatch each one, and build a
  1238→/// read_buffer of BR_* commands to return.
  1239→fn handle_write_read(
  1240→    payload: &[u8],
  1241→    vm_id: u32,
  1242→    host_fd: &Arc<Mutex<Option<RawFd>>>,
  1243→    handles: &Arc<Mutex<HandleTable>>,
  1244→) -> Resp {
  1245→    // Parse the wire header.
  1246→    if payload.len() < 8 {
  1247→        return Resp {
  1248→            ret: -(libc::EINVAL as i32),
  1249→            payload: Vec::new(),
  1250→        };
  1251→    }
  1252→    let write_size = u32::from_ne_bytes(payload[0..4].try_into().unwrap()) as usize;
  1253→    let read_capacity = u32::from_ne_bytes(payload[4..8].try_into().unwrap());
  1254→    if payload.len() < 8 + write_size {
  1255→        warning!(
  1256→            "[KR64][binder][vm{}] BINDER_WRITE_READ: truncated payload (write_size={}, have {})",
  1257→            vm_id,
  1258→            write_size,
  1259→            payload.len() - 8
  1260→        );
  1261→        return Resp {
  1262→            ret: -(libc::EINVAL as i32),
  1263→            payload: Vec::new(),
  1264→        };
  1265→    }
  1266→    let write_buf = &payload[8..8 + write_size];
  1267→
  1268→    // Process each BC_* command in the write buffer.
  1269→    let mut read_buf: Vec<u8> = Vec::new();
  1270→    let mut consumed = 0usize;
  1271→    while consumed + 4 <= write_buf.len() {
  1272→        let cmd = u32::from_ne_bytes(write_buf[consumed..consumed + 4].try_into().unwrap());
  1273→        consumed += 4;
  1274→        let psize = bc_payload_size(cmd) as usize;
  1275→        if consumed + psize > write_buf.len() {
  1276→            warning!(
  1277→                "[KR64][binder][vm{}] truncated BC_* cmd 0x{:08x} (need {}, have {})",
  1278→                vm_id,
  1279→                cmd,
  1280→                psize,
  1281→                write_buf.len() - consumed
  1282→            );
  1283→            break;
  1284→        }
  1285→        let cmd_payload = &write_buf[consumed..consumed + psize];
  1286→        consumed += psize;
  1287→
  1288→        match cmd {
  1289→            BC_TRANSACTION | BC_TRANSACTION_SG => {
  1290→                let result = handle_transaction(cmd_payload, vm_id, host_fd, handles);
  1291→                match result {
  1292→                    TransactionResult::Noop => {
  1293→                        // No reply yet — the guest will keep looping.
  1294→                    }
  1295→                    TransactionResult::Failed => {
  1296→                        push_br_failed_reply(&mut read_buf);
  1297→                    }
  1298→                    TransactionResult::Reply(data) => {
  1299→                        push_br_reply(&mut read_buf, &data);
  1300→                    }
  1301→                }
  1302→            }
  1303→            BC_REPLY | BC_REPLY_SG => {
  1304→                // We're the server side, so we shouldn't receive
  1305→                // BC_REPLY from the guest (the guest is the client).
  1306→                // Log and ignore.
  1307→                info!(
  1308→                    "[KR64][binder][vm{}] BC_REPLY from guest — ignored (skeleton)",
  1309→                    vm_id
  1310→                );
  1311→            }
  1312→            BC_ACQUIRE | BC_RELEASE | BC_INCREFS => {
  1313→                // Strong/weak refcount changes on remote handles. For
  1314→                // the skeleton we accept and ignore — a real impl would
  1315→                // forward these to the host's /dev/binder so the host's
  1316→                // binder driver can manage refcounts on the host's
  1317→                // servicemanager / ActivityManager etc.
  1318→            }
  1319→            BC_ACQUIRE_DONE | BC_INCREFS_DONE | BC_ACQUIRE_FAILED | BC_INCREFS_FAILED => {
  1320→                // Acknowledgements of refcount operations on local
  1321→                // binders. The skeleton doesn't host any local binders
  1322→                // (no guest-side services), so these are no-ops.
  1323→            }
  1324→            BC_FREE_BUFFER | BC_DEAD_BINDER_DONE => {
  1325→                // Return a transaction-data buffer to the kernel, or
  1326→                // acknowledge a death notification. Skeleton: no-op.
  1327→            }
  1328→            BC_ENTER_LOOPER | BC_REGISTER_LOOPER | BC_EXIT_LOOPER => {
  1329→                info!(
  1330→                    "[KR64][binder][vm{}] looper state change: 0x{:08x}",
  1331→                    vm_id, cmd
  1332→                );
  1333→            }
  1334→            BC_REQUEST_DEATH_NOTIFICATION | BC_CLEAR_DEATH_NOTIFICATION => {
  1335→                info!(
  1336→                    "[KR64][binder][vm{}] death-notification request: 0x{:08x}",
  1337→                    vm_id, cmd
  1338→                );
  1339→            }
  1340→            _ => {
  1341→                warning!(
  1342→                    "[KR64][binder][vm{}] unhandled BC_* 0x{:08x} ({} bytes)",
  1343→                    vm_id,
  1344→                    cmd,
  1345→                    psize
  1346→                );
  1347→            }
  1348→        }
  1349→    }
  1350→
  1351→    // If we have read capacity left and produced nothing, push a BR_NOOP
  1352→    // so the guest's looper doesn't busy-spin on empty BINDER_WRITE_READ
  1353→    // returns.
  1354→    if read_buf.is_empty() && read_capacity > 0 {
  1355→        push_br_noop(&mut read_buf);
  1356→    }
  1357→
  1358→    // Build the wire response: [u32 read_size][read_size bytes].
  1359→    let mut resp_payload = Vec::with_capacity(4 + read_buf.len());
  1360→    resp_payload.extend_from_slice(&(read_buf.len() as u32).to_ne_bytes());
  1361→    resp_payload.extend_from_slice(&read_buf);
  1362→
  1363→    Resp {
  1364→        ret: 0,
  1365→        payload: resp_payload,
  1366→    }
  1367→}
  1368→
  1369→// ============================================================================
  1370→// Transaction dispatch — servicemanager vs forward-to-host.
  1371→// ============================================================================
  1372→
  1373→/// Result of handling a `BC_TRANSACTION`.
  1374→enum TransactionResult {
  1375→    /// No reply pushed (transaction accepted, async, or one-way).
  1376→    Noop,
  1377→    /// Push a `BR_FAILED_REPLY` into the read buffer.
  1378→    Failed,
  1379→    /// Push a `BR_REPLY` with the given reply data bytes.
  1380→    Reply(Vec<u8>),
  1381→}
  1382→
  1383→/// Handle a `BC_TRANSACTION` (or `BC_TRANSACTION_SG`) command.
  1384→///
  1385→/// If the target handle is [`SVC_MGR_HANDLE`] (0), this is a
  1386→/// servicemanager transaction and we dispatch to
  1387→/// [`servicemanager_proxy`]. Otherwise we forward to the host's
  1388→/// `/dev/binder` via [`forward_transaction_to_host`].
  1389→fn handle_transaction(
  1390→    cmd_payload: &[u8],
  1391→    vm_id: u32,
  1392→    host_fd: &Arc<Mutex<Option<RawFd>>>,
  1393→    handles: &Arc<Mutex<HandleTable>>,
  1394→) -> TransactionResult {
  1395→    if cmd_payload.len() < std::mem::size_of::<BinderTransactionData>() {
  1396→        warning!(
  1397→            "[KR64][binder][vm{}] BC_TRANSACTION: payload too small ({} < {})",
  1398→            vm_id,
  1399→            cmd_payload.len(),
  1400→            std::mem::size_of::<BinderTransactionData>()
  1401→        );
  1402→        return TransactionResult::Failed;
  1403→    }
  1404→
  1405→    // Parse the fields we care about.
  1406→    let target_handle = u32::from_ne_bytes(cmd_payload[0..4].try_into().unwrap());
  1407→    let code = u32::from_ne_bytes(cmd_payload[16..20].try_into().unwrap());
  1408→    let flags = u32::from_ne_bytes(cmd_payload[20..24].try_into().unwrap());
  1409→
  1410→    if target_handle == SVC_MGR_HANDLE {
  1411→        info!(
  1412→            "[KR64][binder][vm{}] servicemanager transaction: code={} flags=0x{:02x}",
  1413→            vm_id, code, flags
  1414→        );
  1415→        return servicemanager_proxy(cmd_payload, code, handles);
  1416→    }
  1417→
  1418→    info!(
  1419→        "[KR64][binder][vm{}] transaction to handle {}: code={} flags=0x{:02x} — forwarding to host (skeleton)",
  1420→        vm_id, target_handle, code, flags
  1421→    );
  1422→
  1423→    // Skeleton: forward to host. The full implementation would
  1424→    // translate the guest handle to the host handle, patch the
  1425→    // flat_binder_object array, and copy in the data buffer before
  1426→    // issuing the ioctl. This skeleton just issues the raw ioctl with
  1427→    // the unmodified transaction data — which will fail on the host
  1428→    // side (the host's /dev/binder doesn't know about our guest
  1429→    // handles), but it has the right structure.
  1430→    match forward_transaction_to_host(cmd_payload, host_fd) {
  1431→        Ok(reply_bytes) => TransactionResult::Reply(reply_bytes),
  1432→        Err(e) => {
  1433→            warning!(
  1434→                "[KR64][binder][vm{}] forward_transaction_to_host failed: {}",
  1435→                vm_id, e
  1436→            );
  1437→            TransactionResult::Failed
  1438→        }
  1439→    }
  1440→}
  1441→
  1442→/// Intercept servicemanager transactions (target handle 0).
  1443→///
  1444→/// # Parcel layout (AOSP `frameworks/native/libs/binder/IServiceManager.cpp`)
  1445→///
  1446→/// The transaction's data buffer is a parcel:
  1447→///
  1448→/// ```text
  1449→///   i32  strict_mode_policy
  1450→///   i32  work_source
  1451→///   u16[] interface_descriptor_string  (length-prefixed)
  1452→///   …    per-code arguments
  1453→/// ```
  1454→///
  1455→/// For `SVC_MGR_GET_SERVICE` the per-code argument is a length-prefixed
  1456→/// UTF-16 service name string. For `SVC_MGR_ADD_SERVICE` it's the
  1457→/// service name + a strong binder flat object.
  1458→///
  1459→/// # Skeleton behaviour
  1460→///
  1461→/// The skeleton does NOT parse the parcel — it would need to follow the
  1462→/// `binder_transaction_data.data.ptr` pointer into the guest's address
  1463→/// space (which requires either `process_vm_readv` or a shared memory
  1464→/// mapping negotiated via the wire protocol). Instead we log the
  1465→/// request code and return:
  1466→///
  1467→/// * `SVC_MGR_GET_SERVICE` / `SVC_MGR_CHECK_SERVICE` → `Failed` (the
  1468→///   guest will see `BR_FAILED_REPLY` and retry, eventually giving up).
  1469→/// * `SVC_MGR_ADD_SERVICE` → `Noop` (we accept the registration but
  1470→///   don't record anything; in a real impl we'd store the name + handle
  1471→///   in the [`HandleTable`]).
  1472→/// * `SVC_MGR_LIST_SERVICES` → `Failed` (no services to enumerate).
  1473→/// * anything else → `Failed`.
  1474→fn servicemanager_proxy(
  1475→    _cmd_payload: &[u8],
  1476→    code: u32,
  1477→    _handles: &Arc<Mutex<HandleTable>>,
  1478→) -> TransactionResult {
  1479→    match code {
  1480→        SVC_MGR_GET_SERVICE | SVC_MGR_CHECK_SERVICE => {
  1481→            warning!(
  1482→                "[KR64][binder][svc] SVC_MGR_GET_SERVICE/CHECK_SERVICE: skeleton cannot parse parcel"
  1483→            );
  1484→            TransactionResult::Failed
  1485→        }
  1486→        SVC_MGR_ADD_SERVICE => {
  1487→            info!("[KR64][binder][svc] SVC_MGR_ADD_SERVICE accepted (skeleton: not recorded)");
  1488→            TransactionResult::Noop
  1489→        }
  1490→        SVC_MGR_LIST_SERVICES => {
  1491→            info!("[KR64][binder][svc] SVC_MGR_LIST_SERVICES — returning empty (skeleton)");
  1492→            TransactionResult::Failed
  1493→        }
  1494→        _ => {
  1495→            warning!("[KR64][binder][svc] unhandled servicemanager code {}", code);
  1496→            TransactionResult::Failed
  1497→        }
  1498→    }
  1499→}

  1501→/// Forward a `BC_TRANSACTION` to the host's `/dev/binder` via a real
  1502→/// `BINDER_WRITE_READ` ioctl.
  1503→///
  1504→/// # What this does (skeleton)
  1505→///
  1506→/// 1. Lazily opens `/dev/binder` on the host (best-effort; if the open
  1507→///    fails — e.g. on a Linux dev host without the binder module —
  1508→///    returns an error and the caller emits `BR_FAILED_REPLY`).
  1509→/// 2. Builds a `binder_write_read` struct with a write_buffer containing
  1510→///    `[BC_TRANSACTION ioctl number][the guest's transaction_data bytes]`
  1511→///    and an empty read_buffer.
  1512→/// 3. Issues `ioctl(fd, BINDER_WRITE_READ, &bwr)`.
  1513→/// 4. Returns the read_buffer contents (which should start with
  1514→///    `BR_REPLY` + the reply transaction_data) as the reply bytes.
  1515→///
  1516→/// # What this does NOT do (TODO for `BINDER-3`)
  1517→///
  1518→/// * **Handle translation.** The guest's `target_handle` is a number
  1519→///   allocated by *us* (the proxy), not by the host's binder driver.
  1520→///   Before issuing the ioctl, we need to look up the host handle in
  1521→///   the [`HandleTable`] and patch `transaction_data.target.handle`.
  1522→/// * **Flat-binder-object patching.** If the transaction's offsets array
  1523→///   contains any `BINDER_TYPE_HANDLE` / `BINDER_TYPE_WEAK_HANDLE`
  1524→///   objects, those handles ALSO need to be translated. Conversely, any
  1525→///   `BINDER_TYPE_BINDER` / `BINDER_TYPE_WEAK_BINDER` local-binder
  1526→///   pointers need to be translated back in the reply.
  1527→/// * **Data buffer copy-in.** The guest's `data_ptr` is a user pointer
  1528→///   in the guest's address space — we need to copy the data into our
  1529→///   own buffer (or share memory via ashmem) before the kernel can read
  1530→///   it. The skeleton just passes the raw pointer through, which will
  1531→///   cause the kernel to return EFAULT.
  1532→/// * **Reply unparceling.** The reply read_buffer contains a
  1533→///   `BR_REPLY` + `binder_transaction_data` + reply data. We need to
  1534→///   extract the reply data and re-wrap it in our wire format for the
  1535→///   guest.
  1536→fn forward_transaction_to_host(
  1537→    tx_data: &[u8],
  1538→    host_fd: &Arc<Mutex<Option<RawFd>>>,
  1539→) -> io::Result<Vec<u8>> {
  1540→    // Lazily open /dev/binder on the host.
  1541→    let mut guard = host_fd.lock().map_err(|e| {
  1542→        io::Error::new(
  1543→            io::ErrorKind::Other,
  1544→            format!("host_binder_fd mutex poisoned: {}", e),
  1545→        )
  1546→    })?;
  1547→    if guard.is_none() {
  1548→        match open_host_binder() {
  1549→            Ok(fd) => *guard = Some(fd),
  1550→            Err(e) => {
  1551→                return Err(io::Error::new(
  1552→                    io::ErrorKind::Other,
  1553→                    format!("could not open host /dev/binder: {}", e),
  1554→                ));
  1555→            }
  1556→        }
  1557→    }
  1558→    let fd = guard.unwrap();
  1559→
  1560→    // Build the write_buffer: [BC_TRANSACTION][tx_data].
  1561→    let mut write_buf: Vec<u8> = Vec::with_capacity(4 + tx_data.len());
  1562→    write_buf.extend_from_slice(&BC_TRANSACTION.to_ne_bytes());
  1563→    write_buf.extend_from_slice(tx_data);
  1564→
  1565→    // Allocate a read_buffer for the reply. 4 KiB matches what
  1566→    // libbinder.so uses by default.
  1567→    let mut read_buf = vec![0u8; 4096];
  1568→
  1569→    // Construct the binder_write_read struct. The pointers here are
  1570→    // OUR process's pointers (the daemon's), NOT the guest's — this is
  1571→    // the host-side ioctl. The kernel writes back the `*_consumed`
  1572→    // fields, so bwr must be passed mutably.
  1573→    let mut bwr = BinderWriteRead {
  1574→        write_size: write_buf.len() as u64,
  1575→        write_consumed: 0,
  1576→        write_buffer: write_buf.as_ptr() as u64,
  1577→        read_size: read_buf.len() as u64,
  1578→        read_consumed: 0,
  1579→        read_buffer: read_buf.as_mut_ptr() as u64,
  1580→    };
  1581→
  1582→    // Issue the ioctl. libc::ioctl's third arg is c_ulong on Linux;
  1583→    // the kernel reads/writes through the raw pointer.
  1584→    let rc = unsafe {
  1585→        libc::ioctl(
  1586→            fd,
  1587→            BINDER_WRITE_READ as c_ulong,
  1588→            &mut bwr as *mut BinderWriteRead as *mut c_void,
  1589→        )
  1590→    };
  1591→    if rc < 0 {
  1592→        let e = io::Error::last_os_error();
  1593→        return Err(e);
  1594→    }
  1595→
  1596→    // The reply is in read_buf[0..bwr.read_consumed]. For the skeleton
  1597→    // we return the WHOLE read_buffer — a real impl would slice it to
  1598→    // `bwr.read_consumed as usize` and parse out the leading BR_REPLY
  1599→    // + binder_transaction_data + reply-data bytes.
  1600→    let _ = bwr.read_consumed; // TODO(BINDER-3): use this to slice read_buf.
  1601→    Ok(read_buf)
  1602→}
  1603→
  1604→/// Open the host's `/dev/binder` (real char device). Returns the raw FD
  1605→/// on success. The FD is `O_RDWR | O_CLOEXEC`.
  1606→///
  1607→/// On Android this will succeed (the binder module is always loaded).
  1608→/// On a Linux dev host it'll typically fail with ENOENT (no /dev/binder)
  1609→/// or ENODEV (binder module not loaded) — that's fine for `cargo test`.
  1610→fn open_host_binder() -> io::Result<RawFd> {
  1611→    let path = std::ffi::CString::new("/dev/binder").unwrap();
  1612→    let fd = unsafe { libc::open(path.as_ptr(), libc::O_RDWR | libc::O_CLOEXEC) };
  1613→    if fd < 0 {
  1614→        return Err(io::Error::last_os_error());
  1615→    }
  1616→    info!("[KR64][binder] opened host /dev/binder (fd={})", fd);
  1617→    Ok(fd)
  1618→}

  1620→// ============================================================================
  1621→// Wire-framing I/O helpers.
  1622→// ============================================================================
  1623→
  1624→/// Read one [`Frame`] from the stream. Blocks until a full frame is
  1625→/// available. Returns `UnexpectedEof` if the stream closes mid-frame.
  1626→fn read_frame(stream: &mut UnixStream) -> io::Result<Frame> {
  1627→    let mut hdr = [0u8; 8]; // [u32 cmd][u32 arg_len]
  1628→    stream.read_exact(&mut hdr)?;
  1629→    let cmd = u32::from_ne_bytes(hdr[0..4].try_into().unwrap());
  1630→    let arg_len = u32::from_ne_bytes(hdr[4..8].try_into().unwrap()) as usize;
  1631→    let mut payload = vec![0u8; arg_len];
  1632→    stream.read_exact(&mut payload)?;
  1633→    Ok(Frame { cmd, payload })
  1634→}
  1635→
  1636→/// Write one [`Resp`] to the stream.
  1637→fn write_frame(stream: &mut UnixStream, resp: &Resp) -> io::Result<()> {
  1638→    let mut buf = Vec::with_capacity(8 + resp.payload.len());
  1639→    buf.extend_from_slice(&resp.ret.to_ne_bytes());
  1640→    buf.extend_from_slice(&(resp.payload.len() as u32).to_ne_bytes());
  1641→    buf.extend_from_slice(&resp.payload);
  1642→    stream.write_all(&buf)
  1643→}

  1646→// BR_* push helpers (build the read_buffer).
  1647→// ============================================================================
  1648→
  1649→/// Push `[BR_NOOP]` (4 bytes, no payload).
  1650→fn push_br_noop(buf: &mut Vec<u8>) {
  1651→    buf.extend_from_slice(&BR_NOOP.to_ne_bytes());
  1652→}
  1653→
  1654→/// Push `[BR_FAILED_REPLY]` (4 bytes, no payload).
  1655→fn push_br_failed_reply(buf: &mut Vec<u8>) {
  1656→    buf.extend_from_slice(&BR_FAILED_REPLY.to_ne_bytes());
  1657→}
  1658→
  1659→/// Push `[BR_REPLY][binder_transaction_data]` followed by the reply's
  1660→/// data buffer. The `binder_transaction_data` is synthesised with all
  1661→/// fields zeroed except `data_size` / `data_ptr` (which point at the
  1662→/// reply data buffer we're embedding).
  1663→///
  1664→/// NOTE: the guest's libbinder.so expects `data_ptr` to be a pointer
  1665→/// into ITS OWN address space, not ours. The skeleton here just passes
  1666→/// a placeholder pointer — the guest will get garbage if it tries to
  1667→/// dereference it. A real impl would either (a) allocate a buffer in
  1668→/// the guest's address space (via the wire protocol's "shared buffer"
  1669→/// extension) and put the reply data there, or (b) inline the reply
  1670→/// data into the `binder_transaction_data.data.buf[8]` inline array.
  1671→fn push_br_reply(buf: &mut Vec<u8>, reply_data: &[u8]) {
  1672→    buf.extend_from_slice(&BR_REPLY.to_ne_bytes());
  1673→    let tx = BinderTransactionData {
  1674→        data_size: reply_data.len() as u64,
  1675→        ..Default::default()
  1676→    };
  1677→    // Serialize the struct as little-endian bytes. Since the struct is
  1678→    // #[repr(C)] and we're on a little-endian platform (aarch64 /
  1679→    // x86_64), `to_ne_bytes` via raw byte copy works.
  1680→    let tx_bytes: &[u8] = unsafe {
  1681→        std::slice::from_raw_parts(
  1682→            &tx as *const BinderTransactionData as *const u8,
  1683→            std::mem::size_of::<BinderTransactionData>(),
  1684→        )
  1685→    };
  1686→    buf.extend_from_slice(tx_bytes);
  1687→    buf.extend_from_slice(reply_data);
  1688→}

  1690→// ============================================================================
  1691→// BC_* payload-size extraction.
  1692→// ============================================================================
  1693→
  1694→/// Extract the payload size of a BC_* / BR_* command from its ioctl
  1695→/// number. The ioctl number encodes the arg size in bits 16..29
  1696→/// (the `size` field of `_IOC(dir, type, nr, size)`).
  1697→///
  1698→/// For example, `BC_TRANSACTION` = `_IOW('b', 0, sizeof(binder_transaction_data))`
  1699→/// = `(1<<30) | (64<<16) | ('b'<<8) | 0`, so `bc_payload_size(BC_TRANSACTION)`
  1700→/// returns 64.
  1701→fn bc_payload_size(cmd: u32) -> u32 {
  1702→    (cmd >> 16) & 0x3fff
  1703→}
