    18→    18→## TL;DR
    19→    19→
    20→    20→- **Audio.** VM's `AudioService` (a *top-level* service, **not** under `HALManager`) owns two
    21→    21→  lists: `List<AudioTrack>` for playback and `List<AudioRecord>` for capture. JNI
    22→    22→  `nativeStartService(ptr)` opens the virtual `/dev/audio` Unix socket, accepts the guest's
    23→    23→  AudioFlinger connection, and pumps **raw 16-bit PCM** in both directions. Playback runs at
    24→    24→  **44 100 Hz stereo**, capture at **11 025 Hz mono** — these are *not negotiable*, they're
    25→    25→  hard-coded in `acquireAudioTrack`/`acquireAudioRecord`. The native side (`libvm.so`) is the
    26→    26→  bridge: it owns the socket and uses **Java up-calls** (`writeAudioData`, `readRecordData`) to
    27→    27→  push bytes into the host `AudioTrack`/`AudioRecord`. No compressed audio, no resampling, no
    28→    28→  format negotiation — just a fixed-rate PCM pump. Latency is bounded by the host
    29→    29→  `AudioTrack`'s min-buffer-size (typically ~40 ms @ 44.1 kHz stereo 16-bit) and is hidden
    30→    30→  from the guest by AudioFlinger's own buffering.
    31→    31→- **Sensor.** VM's `SensorService` (under `HALManager`) proxies **12 sensor types** through a
    32→    32→  static `SparseIntArray` mapping guest index 0..11 → host `Sensor.TYPE_*`. A 3-bit state mask
    33→    33→  per sensor (`SUPPORTED | ENABLED | ACTIVE`) is mutated by three JNI up-calls
    34→    34→  (`EnableSensors`, `DisableSensors`, `CheckSensorsSupport`) and a fourth (`SetDelay`) for
    35→    35→  sampling period. Host `SensorEvent`s flow Java→native via
    36→    36→  `HALManager.nativeSensorChanged(ptr, idx, tsNs, x, y, z)`. The native side maintains a
    37→    37→  per-sensor subscriber list and writes a 24-byte `{u32 idx, u64 ts, f32 x, f32 y, f32 z}`
    38→    38→  record to the guest sensor HAL socket.
    39→    39→- **Implementation effort.** Audio ≈ 1 new Rust file (~250 LOC) + 1 new Java class (~250 LOC)
    40→    40→  + 1 device entry in `devices.rs` + 1 manifest permission (`RECORD_AUDIO`). Sensor ≈ 1 new
    41→    41→  Rust file (~180 LOC) + 1 new Java class (~300 LOC) + 1 device entry in `devices.rs`. Total
    42→    42→  ~1 day if the JNI dispatch pattern from `input.rs` is followed.

    46→    46→## 1. Audio HAL Virtualization
    47→    47→
    48→    48→### 1.1 Where AudioService sits in the boot graph
    49→    49→
    50→    50→`AudioService` is one of the **top-level services** instantiated by `VMInstance.m5100WoWo()`
    51→    51→alongside `InputService`, `HALManager`, `DisplayService`, `NetlinkManager`, and
    52→    52→`VMEventManager` (see `VM_JAVA_ANALYSIS.md` §2.3):
    53→    53→
    54→    54→```
    55→    55→state 3 (starting_svc):
    56→    56→  ├─ new InputService(this)   → nativeStartService   (/dev/input/touch)
    57→    57→  ├─ new AudioService(this)   → start                (/dev/audio)        ← this one
    58→    58→  ├─ new HALManager(this)     → startHALMgr          (/dev/camera*, /dev/input/sensor, …)
    59→    59→  ├─ new DisplayService(this) → nativeStartService   (/dev/qemu_pipe)
    60→    60→  └─ new NetlinkManager(this) → start                (/dev/netlink_client/*)
    61→    61→```
    62→    62→
    63→    63→Note that Audio is **not** owned by `HALManager` — `HALManager.java`'s private fields are
    64→    64→`mBatteryService, mCameraService, mHWControlService, mLocationService, mPhoneService,
    65→    65→mSensorService, mWiFiService`. Audio stands alone because, like Input and Display, it has a
    66→    66→hard real-time requirement (a single blocked `write()` on the PCM path causes an audible
    67→    67→glitch), so it gets its own dedicated thread and its own native pointer.
    68→    68→
    69→    69→### 1.2 How VM creates `/dev/audio`
    70→    70→
    71→    71→There is **no Java-side `mknod()`**. The native `libkr64.so` daemon creates the socket file
    72→    72→inside the guest rootfs's `/dev` directory using `mknodat(S_IFSOCK|0666)` followed by
    73→    73→`bind(2)` (see `devices.rs` comment block at line 22–35 — twoyi already mirrors this). Once
    74→    74→the socket file exists in `/dev/audio`, the guest's `init` starts `audioserver` which starts
    75→    75→`AudioFlinger`; `AudioFlinger`'s ALSA HAL module does a `connect(2)` on `/dev/audio`, and
    76→    76→from that point on the host's `libvm.so` is on the other end of the socket.
    77→    77→
    78→    78→> In twoyi the same mechanism is used by `create_qemu_pipe`, `create_touch_device`, and
    79→    79→> `create_key_device` in `app/rs/kr64/src/devices.rs`. Adding `create_audio_device(rootfs)`
    80→    80→> is the one-line change to extend the same pattern.

    82→    82→### 1.3 The audio data flow (guest → host)
    83→    83→
    84→    84→```
    85→    85→                 Guest Android                                Host (libvm.so + Java)
    86→    86→  ┌─────────────────────────────────────┐    ┌─────────────────────────────────────────────┐
    87→    87→  │  AudioFlinger::PlaybackThread       │    │  libvm.so audio pump thread                 │
    88→    88→  │    mixer → PCM_16BIT @ 44100 stereo │    │                                             │
    89→    89→  │       │                             │    │   ┌─────────────────────────────────────┐  │
    90→    90→  │       ▼                             │    │   │ per-connection state:               │  │
    91→    91→  │  AudioHAL::out_write(buf, bytes)    │    │   │   AudioTrack* jtrack;               │  │
    92→    92→  │       │                             │    │   │   int      minBuf;                  │  │
    93→    93→  │       ▼                             │    │   │   direction = PLAYBACK;             │  │
    94→    94→  │  write(/dev/audio, buf, bytes)      │───┼──▶│                                     │  │
    95→    95→  │       (blocking socket write)       │    │   │  recv(sock, tmpBuf, minBuf)         │  │
    96→    96→  │                                     │    │   │     │                               │  │
    97→    97→  │                                     │    │   │     ▼  JNI up-call                  │  │
    98→    98→  │                                     │    │   │  AudioService.writeAudioData(       │  │
    99→    99→  │                                     │    │   │      jtrack, tmpBuf, 0, n)          │  │
   100→   100→  │                                     │    │   │     │                               │  │
   101→   101→  │                                     │    │   │     ▼                               │  │
   102→   102→  │                                     │    │   │  AudioTrack.write(buf, off, len) ◀──┘  │
   103→   103→  │                                     │    │   │  →  bytes pushed into host mixer       │
   104→   104→  └─────────────────────────────────────┘    └─────────────────────────────────────────────┘
   105→   105→```
   106→   106→
   107→   107→The reverse flow (host microphone → guest) is symmetric: `libvm.so` calls Java
   108→   108→`readRecordData(record, buf, 0, len)` to pull bytes out of the host `AudioRecord`, then
   109→   109→`write(sock, buf, n)` to push them into the guest's `AudioFlinger::RecordThread`.
   110→   110→
   111→   111→**Key insight:** `libvm.so` is *not* a thin passthrough — it owns the per-connection state
   112→   112→machine (the `jtrack` / `jrecord` jobject references, the buffer, the polling loop). The Java
   113→   113→side just owns the AudioTrack/AudioRecord **lifecycle**. This split is what lets the native
   114→   114→side run on a SCHED_FIFO thread if needed without crossing the JNI boundary on every byte.
   115→   115→

   127→   127→### 1.5 Native (JNI) functions
   128→   128→
   129→   129→Decompiled from `AudioService.java` (lines 122–128) — note that **all native methods are
   130→   130→private instance methods on `AudioService`**, taking the `mNativePtr` as the first arg:
   131→   131→
   132→   132→```java
   133→   133→private native long nativeSetup(int vmId);        // returns opaque dispatcher pointer
   134→   134→private native int  nativeStartService(long ptr); // opens /dev/audio, starts accept loop
   135→   135→private native int  nativeStopService(long ptr);  // closes sockets, releases all tracks
   136→   136→private native void nativeDispose(long ptr);      // frees the dispatcher
   137→   137→```
   138→   138→
   139→   139→And the **callbacks the native side makes back into Java** (these are the ones `libvm.so`
   140→   140→invokes from inside the pump loop):
   141→   141→
   142→   142→```java
   143→   143→private AudioTrack acquireAudioTrack(int[] outMinBuf); // returns a playing AudioTrack
   144→   144→private AudioRecord acquireAudioRecord(int[] outMinBuf); // returns a recording AudioRecord
   145→   145→private int  writeAudioData(AudioTrack t, byte[] buf, int off, int len);  // returns bytes written
   146→   146→private int  readRecordData(AudioRecord r, byte[] buf, int off, int len); // returns bytes read
   147→   147→private void releaseAudioTrack(AudioTrack t);
   148→   148→private void releaseAudioRecord(AudioRecord r);
   149→   149→private void clearAudioTrack();   // release all
   150→   150→private void clearAudioRecord();  // release all
   151→   151→```
   152→   152→
   153→   153→`acquireAudioTrack` / `acquireAudioRecord` are called once per guest **connection** (the
   154→   154→guest may open `/dev/audio` multiple times, e.g. for ringtone + media). The `int[1] outMinBuf`
   155→   155→parameter is used to communicate the host's min-buffer-size back to native, which then sizes
   156→   156→its scratch buffer accordingly.

   158→   158→### 1.6 Audio format
   159→   159→
   160→   160→Hard-coded in `acquireAudioTrack` / `acquireAudioRecord` (verbatim from decompiled source):
   161→   161→
   162→   162→```java
   163→   163→// Playback (lines 71-72):
   164→   164→int minBufferSize = AudioTrack.getMinBufferSize(44100, 3, 2);
   165→   165→AudioTrack audioTrack = new AudioTrack(3, 44100, 3, 2, minBufferSize, 1);
   166→   166→//   streamType      = 3                  = STREAM_MUSIC
   167→   167→//   sampleRateInHz  = 44100              = 44.1 kHz
   168→   168→//   channelConfig   = 3                  = CHANNEL_OUT_STEREO
   169→   169→//   audioFormat     = 2                  = ENCODING_PCM_16BIT
   170→   170→//   mode            = 1                  = MODE_STREAM
   171→   171→
   172→   172→// Capture (lines 52-53):
   173→   173→int minBufferSize = AudioRecord.getMinBufferSize(11025, 2, 2);
   174→   174→AudioRecord audioRecord = new AudioRecord(1, 11025, 2, 2, minBufferSize);
   175→   175→//   audioSource     = 1                  = MIC
   176→   176→//   sampleRateInHz  = 11025              = 11.025 kHz  ← note: NOT 44.1, voice rate
   177→   177→//   channelConfig   = 2                  = CHANNEL_IN_MONO
   178→   178→//   audioFormat     = 2                  = ENCODING_PCM_16BIT
   179→   179→```
   180→   180→
   181→   181→**Format is uncompressed PCM_16BIT.** No MP3, no AAC, no Opus. The guest's `AudioFlinger`
   182→   182→does all the decoding/resampling before it writes to `/dev/audio`. The host's `AudioTrack`
   183→   183→gets the final mix and just routes it to the speaker.
   184→   184→
   185→   185→This means twoyi's audio device handler can be **completely format-agnostic** at the protocol
   186→   186→level — it's just a byte pipe with a small fixed header. The sample-rate mismatch (44 100 vs
   187→   187→11 025) between playback and capture is fine because they are independent connections with
   188→   188→independent `AudioTrack`/`AudioRecord` objects.
   189→   189→
   190→   190→### 1.7 Latency handling
   191→   191→
   192→   192→Three latency layers, in order of decreasing impact:
   193→   193→
   194→   194→1. **Host AudioTrack min-buffer-size** (~125 ms typical on a Pixel for STREAM_MUSIC @ 44.1 kHz
   195→   195→   stereo 16-bit). This is the time between `AudioTrack.write()` returning and the first
   196→   196→   sample hitting the speaker. AudioFlinger's mixer thread reads from this buffer.
   197→   197→2. **Socket-level buffering.** `libvm.so` uses raw `recv()`/`send()` on the `/dev/audio`
   198→   198→   socket; the default socket buffer is ~128 KiB on Android. At 176 KB/s (44.1 kHz × 16-bit ×
   199→   199→   stereo) that's ~0.7 s of slack, but in practice the pump loop runs as fast as the host
   200→   200→   `AudioTrack` consumes, so the socket buffer stays near-empty.
   201→   201→3. **Guest AudioFlinger mixer latency.** Standard Android value, ~40–80 ms; invisible to twoyi.
   202→   202→
   203→   203→VM does **not** do anything fancy here — no SCHED_FIFO, no ASIO, no AAudio (the code predates
   204→   204→AAudio's wide deployment). The latency budget is just `host AudioTrack latency + socket
   205→   205→buffer ≈ 200–300 ms`. For a rhythm game this is high; the user will notice. The fix isn't in
   206→   206→the HAL layer though — it's in switching the host side to **AAudio with `setBufferSizeInFrames`
   207→   207→set low** and `setPerformanceMode(PERFORMANCE_MODE_LOW_LATENCY)`. That's a Java-side swap
   208→   208→(`AudioTrack` → `AAudioStream`) and doesn't change the Rust pump at all.

   225→   225→### 2.1 The 12-sensor mapping
   226→   226→
   227→   227→Decompiled verbatim from `SensorService.java` lines 61–74 (the `static {}` block). The
   228→   228→`SparseIntArray f9098WWWW` maps **guest sensor index (0..11) → host `Sensor.TYPE_*`**:
   229→   229→
   230→   230→| Guest idx | `Sensor.TYPE_*` | Constant name | Notes |
   231→   231→|---:|---:|---|---|
   232→   232→| 0  | 1  | `TYPE_ACCELEROMETER`            | Most-used; required for auto-rotate + games |
   233→   233→| 1  | 2  | `TYPE_MAGNETIC_FIELD`           | Compass |
   234→   234→| 2  | 3  | `TYPE_ORIENTATION`              | Deprecated in API 8 but still emulated |
   235→   235→| 3  | 7  | `TYPE_TEMPERATURE`              | Ambient |
   236→   236→| 4  | 8  | `TYPE_LIGHT`                    | Ambient light |
   237→   237→| 5  | 5  | `TYPE_PROXIMITY`                | Face-detect during calls |
   238→   238→| 6  | 6  | `TYPE_GYROSCOPE`                | VR/games |
   239→   239→| 7  | 12 | `TYPE_RELATIVE_HUMIDITY`        | Rare |
   240→   240→| 8  | 9  | `TYPE_PRESSURE`                 | Barometer |
   241→   241→| 9  | 19 | `TYPE_GRAVITY`                  | Derived from accel+gyro |
   242→   242→| 10 | 18 | `TYPE_STEP_DETECTOR`            | Pedometer |
   243→   243→| 11 | 4  | `TYPE_GYROSCOPE_UNCALIBRATED`   | Raw gyro with bias |
   244→   244→
   245→   245→The order is **not contiguous by `TYPE_*` value** — it's the order the guest's sensor HAL
   246→   246→expects to enumerate them. The guest's `sensorservice` opens the virtual `/dev/input/sensor`
   247→   247→device and asks "how many sensors?" — the answer is 12 — and then queries each by index
   248→   248→0..11. The Java side translates that index to the host's `Sensor.TYPE_*` via this table.
   249→   249→
   250→   250→### 2.2 Device paths
   251→   251→
   252→   252→VM does not expose 12 separate device nodes. There's a single **multiplexed** virtual sensor
   253→   253→device — inferred from `VM_KR64_ANALYSIS.md` (it's listed in the device inventory but not in
   254→   254→the MVP subset that twoyi has today). The path is most likely `{rootfs}/dev/input/sensor` (a
   255→   255→Unix socket), matching the input device pattern.
   256→   256→
   257→   257→The wire format per sensor event is inferred to be a 24-byte record (matches
   258→   258→`nativeSensorChanged`'s signature: `int idx, long ts, float x, float y, float z`):
   259→   259→
   260→   260→```
   261→   261→struct sensor_event {
   262→   262→    uint32_t sensor_idx;   // 0..11
   263→   263→    uint64_t timestamp_ns; // SystemClock.elapsedRealtimeNanos()
   264→   264→    float    values[3];    // x, y, z  (unused slots are 0)
   265→   265→} __attribute__((packed));  // 4 + 8 + 12 = 24 bytes
   266→   266→```
   267→   267→
   268→   268→Plus a small control protocol for enable/disable/set-delay — likely 8-byte TLV-style
   269→   269→`{u32 cmd, u32 idx, u32 arg}` requests.

   305→   305→### 2.5 The 3-bit state machine
   306→   306→
   307→   307→Each of the 12 entries in `f9102WWWWWWWW` (an `int[12]`) holds a bitmask:
   308→   308→
   309→   309→| Bit | Mask | Name | Meaning |
   310→   310→|---:|---:|---|---|
   311→   311→| 0 | `1` | SUPPORTED | Host has this sensor (`getDefaultSensor()` returned non-null) |
   312→   312→| 1 | `2` | ENABLED   | Guest requested enable |
   313→   313→| 2 | `4` | ACTIVE    | `SensorManager.registerListener` was called |
   314→   314→
   315→   315→The state transitions (from `HALManager.java`):
   316→   316→
   317→   317→- **`CheckSensorsSupport(int idx)`** (line 178): returns `(state[idx] & 1) == 1`. Called by
   318→   318→  native when the guest asks "do you have sensor N?".
   319→   319→- **`EnableSensors(int idx)`** (line 200): if `(state[idx] & 2) == 2` (i.e. guest has
   320→   320→  requested enable), set `state[idx] |= 4` and call `SensorManager.registerListener(this,
   321→   321→  sensor, samplingPeriodUs, maxReportLatencyUs, handler)`. Only actually registers if
   322→   322→  `f9104WWWWWWWW` (the foreground flag) is true.
   323→   323→- **`DisableSensors(int idx)`** (line 187): `state[idx] &= ~4`, call
   324→   324→  `SensorManager.unregisterListener(this, sensor)`.
   325→   325→- **`SetDelay(int idx, int delay)`** (line 561): zeros out `f9108WWoWWo[idx]` and
   326→   326→  `f9103WWWWWWWW[idx]`. (Yes, this looks like a decompiler artifact, but the bytecode
   327→   327→  matches — VM really does zero both fields. The actual sampling period used is then `1` if
   328→   328→  `0`, per line 211–213. Treat this as a quirk to mirror, not a bug to fix.)
   329→   329→
   330→   330→### 2.6 Foreground/background awareness
   331→   331→
   332→   332→`HALManager.onBackground()` (line 719) sets `f9104WWWWWWWW = false` and unregisters all
   333→   333→ACTIVE sensors. `HALManager.onForeground()` (line 759) flips it back and re-registers
   334→   334→everything. This is critical for power — when the user backgrounds the VM, the host sensor
   335→   335→pipeline shuts down. Twoyi should do the same in `Activity.onPause()/onResume()`.
   336→   336→
   337→   337→### 2.7 Implementation approach for twoyi
   338→   338→
   339→   339→| Aspect | Plan |
   340→   340→|---|---|
   341→   341→| **Java side** | New `io.twoyi.hal.SensorService.java` — port the `SparseIntArray` table verbatim. Implement `SensorEventListener.onSensorChanged` to call `HALManager.sensorChanged(idx, ts, x, y, z)`. Add foreground/background hooks. |
   342→   342→| **Native side** | New `app/rs/kr64/src/sensors.rs` — accept loop on `/dev/input/sensor`. Read control messages (`ENABLE`, `DISABLE`, `SET_DELAY`, `CHECK_SUPPORT`) and dispatch via JNI to Java. Push `sensor_event` records from a queue filled by `nativeSensorChanged`. |
   343→   343→| **Device path** | Extend `devices.rs` with `create_sensor_device(rootfs)` returning a `DeviceSocket` bound to `{rootfs}/dev/input/sensor`. |
   344→   344→| **Manifest** | Add `<uses-permission android:name="android.permission.HIGH_SAMPLING_RATE_SENSORS" />` (Android 12+, needed for >200 Hz). Normal accel/gyro/mag don't need any permission. |
   345→   345→| **MVP shortcut** | Implement only idx 0 (accel), 1 (mag), 6 (gyro) — these cover 95% of real apps. Return `false` from `CheckSensorsSupport` for the other 9 indices. ~50% less code. |

   351→   351→### 3.1 `app/rs/kr64/src/audio.rs` (pseudo-Rust)
   352→   352→
   353→   353→This file lives in the kr64 daemon (next to `devices.rs`). It owns the audio accept/pump
   354→   354→loop. Mirrors the existing pattern in `app/rs/src/input.rs` (touch/key servers).
   355→   355→
   356→   356→```rust
   357→   357→//! Virtual `/dev/audio` — bidirectional PCM pump.
   358→   358→//!
   359→   359→//! One thread per connection. Two connection classes:
   360→   360→//!   - PLAYBACK:  guest writes PCM, we call AudioTrack.write()
   361→   361→//!   - CAPTURE:   we call AudioRecord.read(), then write PCM to guest
   362→   362→//!
   363→   363→//! Wire protocol (header sent by guest on connect):
   364→   364→//!   struct audio_header {
   365→   365→//!       uint32_t magic;       // 'AUDO' = 0x4F444D41
   366→   366→//!       uint32_t direction;   // 1 = PLAYBACK, 2 = CAPTURE
   367→   367→//!       uint32_t sample_rate; // ignored — VM hard-codes 44100/11025
   368→   368→//!       uint32_t channels;    // ignored — VM hard-codes stereo/mono
   369→   369→//!   }  // 16 bytes
   370→   370→
   371→   371→use std::os::unix::net::{UnixListener, UnixStream};
   372→   372→use std::os::unix::io::AsRawFd;
   373→   373→use std::thread;
   374→   374→use crate::devices::DeviceSocket;
   375→   375→use crate::{info, warning};
   376→   376→
   377→   377→const AUDIO_HEADER_MAGIC:   u32 = 0x4F444D41; // 'AUDO'
   378→   378→const AUDIO_DIR_PLAYBACK:    u32 = 1;
   379→   379→const AUDIO_DIR_CAPTURE:     u32 = 2;
   380→   380→const PLAYBACK_SAMPLE_RATE:  i32 = 44_100;
   381→   381→const CAPTURE_SAMPLE_RATE:   i32 = 11_025;
   382→   382→
   383→   383→/// Per-connection state. Held by the pump thread.
   384→   384→struct AudioConn {
   385→   385→    stream: UnixStream,
   386→   386→    direction: u32,
   387→   387→    // JNI env cached on first up-call (thread-local):
   388→   388→    jvm: *mut jni::JavaVM,
   389→   389→    audio_service: jni::sys::jobject, // global ref to Java AudioService
   390→   390→}
   391→   391→
   392→   392→/// Start the audio server. Spawned by `lib.rs` main loop after
   393→   393→/// `create_audio_device(rootfs)` returns the bound listener.
   394→   394→pub fn start_audio_server(dev: DeviceSocket, jvm: *mut jni::JavaVM, audio_svc: jni::sys::jobject) {
   395→   395→    let listener = dev.take_listener().expect("audio listener taken");
   396→   396→    thread::spawn(move || {
   397→   397→        info!("[KR64][audio] server listening");
   398→   398→        for stream in listener.incoming() {
   399→   399→            match stream {
   400→   400→                Ok(s) => {
   401→   401→                    let conn = AudioConn {
   402→   402→                        stream: s,
   403→   403→                        direction: 0, // unknown until header read
   404→   404→                        jvm,
   405→   405→                        audio_service: audio_svc, // global ref, shared
   406→   406→                    };
   407→   407→                    // One thread per connection — matches VM's per-track model.
   408→   408→                    thread::spawn(move || handle_audio_conn(conn));
   409→   409→                }
   410→   410→                Err(e) => warning!("[KR64][audio] accept failed: {}", e),
   411→   411→            }
   412→   412→        }
   413→   413→    });
   414→   414→}
   415→   415→
   416→   416→fn handle_audio_conn(mut conn: AudioConn) {
   417→   417→    // 1. Read the 16-byte header.
   418→   418→    let mut hdr = [0u8; 16];
   419→   419→    if read_exact(&mut conn.stream, &mut hdr).is_err() {
   420→   420→        return;
   421→   421→    }
   422→   422→    let magic     = u32::from_le_bytes(hdr[0..4]);  let _ = magic;
   423→   423→    let direction = u32::from_le_bytes(hdr[4..8]);
   424→   424→    conn.direction = direction;
   425→   425→    // sample_rate and channels are ignored — VM hard-codes them.
   426→   426→
   427→   427→    match direction {
   428→   428→        AUDIO_DIR_PLAYBACK => handle_playback(conn),
   429→   429→        AUDIO_DIR_CAPTURE  => handle_capture(conn),
   430→   430→        _ => warning!("[KR64][audio] unknown direction {}", direction),
   431→   431→    }
   432→   432→}
   433→   433→
   434→   434→fn handle_playback(conn: AudioConn) {
   435→   435→    // 2. Up-call: AudioService.acquireAudioTrack(int[1] outMinBuf)
   436→   436→    let (track, min_buf) = jni_acquire_audio_track(conn.jvm, conn.audio_service);
   437→   437→    if track.is_null() { return; }
   438→   438→
   439→   439→    // 3. Pump loop: read PCM from socket, push into AudioTrack.
   440→   440→    let mut buf = vec![0u8; min_buf as usize];
   441→   441→    loop {
   442→   442→        let n = match read_exact(&conn.stream, &mut buf[..min_buf as usize]) {
   443→   443→            Ok(()) => min_buf as i32,
   444→   444→            Err(_) => break,
   445→   445→        };
   446→   446→        // JNI up-call: AudioService.writeAudioData(track, buf, 0, n)
   447→   447→        let written = jni_write_audio_data(conn.jvm, conn.audio_service, track, &buf[..n as usize]);
   448→   448→        if written <= 0 { break; }
   449→   449→    }
   450→   450→
   451→   451→    // 4. Release on disconnect.
   452→   452→    jni_release_audio_track(conn.jvm, conn.audio_service, track);
   453→   453→}
   454→   454→
   455→   455→fn handle_capture(conn: AudioConn) {
   456→   456→    let (record, min_buf) = jni_acquire_audio_record(conn.jvm, conn.audio_service);
   457→   457→    if record.is_null() { return; } // permission denied or unsupported
   458→   458→
   459→   459→    let mut buf = vec![0u8; min_buf as usize];
   460→   460→    loop {
   461→   461→        // JNI up-call: AudioService.readRecordData(record, buf, 0, min_buf)
   462→   462→        let n = jni_read_record_data(conn.jvm, conn.audio_service, record, &mut buf[..]);
   463→   463→        if n <= 0 { break; }
   464→   464→        if write_all(&conn.stream, &buf[..n as usize]).is_err() { break; }
   465→   465→    }
   466→   466→
   467→   467→    jni_release_audio_record(conn.jvm, conn.audio_service, record);
   468→   468→}
   469→   469→
   470→   470→// ===== JNI up-call shims (would use the `jni` crate in practice) ==========
   471→   471→//
   472→   472→// These mirror VM's `acquireAudioTrack`, `acquireAudioRecord`, `writeAudioData`,
   473→   473→// `readRecordData`, `releaseAudioTrack`, `releaseAudioRecord` private methods.
   474→   474→// Each one:
   475→   475→//   1. Attaches the current thread to the JVM (cached in thread-local).
   476→   476→//   2. Finds the AudioService class + method by signature.
   477→   477→//   3. Calls the method, marshals args/returns.
   478→   478→//   4. Returns the Java object ref (for acquire) or the int (for read/write).
   479→   479→
   480→   480→fn jni_acquire_audio_track(jvm: *mut jni::JavaVM, svc: jni::sys::jobject)
   481→   481→    -> (jni::sys::jobject, i32) { /* … */ (std::ptr::null_mut(), 0) }
   482→   482→fn jni_acquire_audio_record(jvm: *mut jni::JavaVM, svc: jni::sys::jobject)
   483→   483→    -> (jni::sys::jobject, i32) { /* … */ (std::ptr::null_mut(), 0) }
   484→   484→fn jni_write_audio_data(jvm: *mut jni::JavaVM, svc: jni::sys::jobject,
   485→   485→    track: jni::sys::jobject, buf: &[u8]) -> i32 { /* … */ 0 }
   486→   486→fn jni_read_record_data(jvm: *mut jni::JavaVM, svc: jni::sys::jobject,
   487→   487→    record: jni::sys::jobject, buf: &mut [u8]) -> i32 { /* … */ 0 }
   488→   488→fn jni_release_audio_track(jvm: *mut jni::JavaVM, svc: jni::sys::jobject,
   489→   489→    track: jni::sys::jobject) { /* … */ }
   490→   490→fn jni_release_audio_record(jvm: *mut jni::JavaVM, svc: jni::sys::jobject,
   491→   491→    record: jni::sys::jobject) { /* … */ }
   492→   492→
   493→   493→// ===== I/O helpers =======================================================
   494→   494→fn read_exact(s: &UnixStream, buf: &mut [u8]) -> std::io::Result<()> {
   495→   495→    use std::io::Read;
   496→   496→    let mut filled = 0;
   497→   497→    while filled < buf.len() {
   498→   498→        let n = s.read(&mut buf[filled..])?;
   499→   499→        if n == 0 { return Err(std::io::ErrorKind::UnexpectedEof.into()); }
   500→   500→        filled += n;
   501→   501→    }
   502→   502→    Ok(())
   503→   503→}
   504→   504→
   505→   505→fn write_all(s: &UnixStream, buf: &[u8]) -> std::io::Result<()> {
   506→   506→    use std::io::Write;
   507→   507→    s.write_all(buf)
   508→   508→}
   509→   509→```

   511→   511→### 3.2 `app/rs/kr64/src/sensors.rs` (pseudo-Rust)
   512→   512→
   513→   513→```rust
   514→   514→//! Virtual `/dev/input/sensor` — multiplexed 12-sensor HAL.
   515→   515→//!
   516→   516→//! Wire protocol:
   517→   517→//!   Control (guest → host, 12 bytes per request):
   518→   518→//!     struct sensor_ctl {
   519→   519→//!         uint32_t cmd;   // 1=ENABLE, 2=DISABLE, 3=CHECK_SUPPORT, 4=SET_DELAY
   520→   520→//!         uint32_t idx;   // 0..11
   521→   521→//!         uint32_t arg;   // sampling period us (for SET_DELAY)
   522→   522→//!     }
   523→   523→//!   Event (host → guest, 24 bytes per event, see §2.2):
   524→   524→//!     struct sensor_event { uint32_t idx; uint64_t ts; float x,y,z; }
   525→   525→//!
   526→   526→//! Single accept loop, single connection (the guest's sensorservice).
   527→   527→
   528→   528→use std::os::unix::net::UnixStream;
   529→   529→use std::sync::mpsc;
   530→   530→use std::thread;
   531→   531→use crate::devices::DeviceSocket;
   532→   532→use crate::{info, warning};
   533→   533→
   534→   534→const CTL_ENABLE:        u32 = 1;
   535→   535→const CTL_DISABLE:       u32 = 2;
   536→   536→const CTL_CHECK_SUPPORT: u32 = 3;
   537→   537→const CTL_SET_DELAY:     u32 = 4;
   538→   538→
   539→   539→/// 24-byte sensor event, packed for wire compat.
   540→   540→#[repr(C, packed)]
   541→   541→struct SensorEvent {
   542→   542→    idx: u32,
   543→   543→    ts:  u64,
   544→   544→    x:   f32,
   545→   545→    y:   f32,
   546→   546→    z:   f32,
   547→   547→}
   548→   548→const _: () = assert!(std::mem::size_of::<SensorEvent>() == 24);
   549→   549→
   550→   550→pub fn start_sensor_server(
   551→   551→    dev: DeviceSocket,
   552→   552→    jvm: *mut jni::JavaVM,
   553→   553→    hal_mgr: jni::sys::jobject,
   554→   554→) {
   555→   555→    let listener = dev.take_listener().expect("sensor listener taken");
   556→   556→
   557→   557→    // Single connection expected — guest's sensorservice holds it for the
   558→   558→    // lifetime of the guest. We still loop so reboots don't kill us.
   559→   559→    thread::spawn(move || {
   560→   560→        info!("[KR64][sensor] server listening");
   561→   561→        for stream in listener.incoming() {
   562→   562→            match stream {
   563→   563→                Ok(s) => {
   564→   564→                    let (tx, rx) = mpsc::channel::<SensorEvent>();
   565→   565→                    // Spawn the event-pump thread (host → guest).
   566→   566→                    let mut s_ev = s.try_clone().expect("clone sensor stream");
   567→   567→                    thread::spawn(move || pump_events(&mut s_ev, rx));
   568→   568→                    // Spawn the control thread (guest → host).
   569→   569→                    let mut s_ctl = s;
   570→   570→                    thread::spawn(move || handle_control(&mut s_ctl, jvm, hal_mgr, tx));
   571→   571→                }
   572→   572→                Err(e) => warning!("[KR64][sensor] accept failed: {}", e),
   573→   573→            }
   574→   574→        }
   575→   575→    });
   576→   576→}
   577→   577→
   578→   578→/// Read control requests from guest, dispatch to Java, push events to pump.
   579→   579→fn handle_control(
   580→   580→    s: &mut UnixStream,
   581→   581→    jvm: *mut jni::JavaVM,
   582→   582→    hal_mgr: jni::sys::jobject,
   583→   583→    _tx: mpsc::Sender<SensorEvent>,
   584→   584→) {
   585→   585→    let mut buf = [0u8; 12];
   586→   586→    loop {
   587→   587→        if read_exact(s, &mut buf).is_err() { return; }
   588→   588→        let cmd = u32::from_le_bytes(buf[0..4]);
   589→   589→        let idx = u32::from_le_bytes(buf[4..8]);
   590→   590→        let arg = u32::from_le_bytes(buf[8..12]);
   591→   591→
   592→   592→        match cmd {
   593→   593→            CTL_ENABLE => {
   594→   594→                // JNI: HALManager.EnableSensors(idx)
   595→   595→                let _ = jni_enable_sensors(jvm, hal_mgr, idx as i32);
   596→   596→                // Now stash `tx` in a per-idx map so nativeSensorChanged knows
   597→   597→                // where to send events. (In practice this lives in the
   598→   598→                // dispatcher struct, not a local — see §3.3.)
   599→   599→            }
   600→   600→            CTL_DISABLE => {
   601→   601→                let _ = jni_disable_sensors(jvm, hal_mgr, idx as i32);
   602→   602→            }
   603→   603→            CTL_CHECK_SUPPORT => {
   604→   604→                let supported = jni_check_sensors_support(jvm, hal_mgr, idx as i32);
   605→   605→                // Reply: 4-byte bool.
   606→   606→                let _ = s.write_all(&[supported as u8; 4]);
   607→   607→            }
   608→   608→            CTL_SET_DELAY => {
   609→   609→                let _ = jni_set_delay(jvm, hal_mgr, idx as i32, arg as i32);
   610→   610→            }
   611→   611→            _ => warning!("[KR64][sensor] unknown ctl cmd={} idx={}", cmd, idx),
   612→   612→        }
   613→   613→    }
   614→   614→}
   615→   615→
   616→   616→/// Drain the event queue and write 24-byte records to the guest.
   617→   617→/// This is the consumer side of `nativeSensorChanged`.
   618→   618→fn pump_events(s: &mut UnixStream, rx: mpsc::Receiver<SensorEvent>) {
   619→   619→    for ev in rx {
   620→   620→        let bytes: &[u8; 24] = unsafe {
   621→   621→            std::slice::from_raw_parts(&ev as *const SensorEvent as *const u8, 24)
   622→   622→                .try_into().unwrap()
   623→   623→        };
   624→   624→        if s.write_all(bytes).is_err() { return; }
   625→   625→    }
   626→   626→}
   627→   627→
   628→   628→// ===== JNI shims (signature-identical to VM's HALManager private methods) =
   629→   629→fn jni_enable_sensors(jvm: *mut jni::JavaVM, hal: jni::sys::jobject, idx: i32) -> bool { /* … */ false }
   630→   630→fn jni_disable_sensors(jvm: *mut jni::JavaVM, hal: jni::sys::jobject, idx: i32) { /* … */ }
   631→   631→fn jni_check_sensors_support(jvm: *mut jni::JavaVM, hal: jni::sys::jobject, idx: i32) -> bool { /* … */ false }
   632→   632→fn jni_set_delay(jvm: *mut jni::JavaVM, hal: jni::sys::jobject, idx: i32, delay: i32) { /* … */ }
   633→   633→
   634→   634→// `nativeSensorChanged` is the *down-call* from Java → Rust. It would be
   635→   635→// exposed as a `#[no_mangle] pub extern "system" fn Java_io_twoyi_hal_...`
   636→   636→// symbol that pushes a SensorEvent into the per-idx mpsc::Sender.
   637→   637→
   638→   638→// ===== I/O helpers (same as audio.rs) ====================================
   639→   639→fn read_exact(s: &UnixStream, buf: &mut [u8]) -> std::io::Result<()> { /* … */ Ok(()) }
   640→   640→```

   716→   716→## 4. Open questions / risks
   717→   717→
   718→   718→1. **Guest's `/dev/audio` driver.** Twoyi's guest ROM (an AOSP GSI) needs a working
   719→   719→   `audio.primary.<board>.so` HAL module that opens `/dev/audio` as a Unix socket (not the
   720→   720→   ALSA tinyalsa path). VM's ROM ships a custom HAL that does this; twoyi's GSI may need the
   721→   721→   same patch. **Action:** audit the guest's `audio.primary.default.so` to confirm it speaks
   722→   722→   the Unix-socket protocol, not tinyalsa `/dev/snd/*`. If it speaks tinyalsa, we need a
   723→   723→   different approach (either swap the HAL module or implement `/dev/snd/controlC0`,
   724→   724→   `/dev/snd/pcmC0D0p`, `/dev/snd/pcmC0D0c` — substantially more work).
   725→   725→2. **Sensor HAL module.** Same concern — the guest's `sensors.<board>.so` needs to open
   726→   726→   `/dev/input/sensor` as a socket. VM's ROM has this; the GSI may not.
   727→   727→3. **AAudio vs AudioTrack.** For real rhythm-game latency, switching to AAudio is
   728→   728→   recommended. This is a Java-only change but requires API 26+ (we target API 21+). Gate
   729→   729→   behind `Build.VERSION.SDK_INT >= 26`.
   730→   730→4. **Threading.** Each audio connection needs its own Rust thread. The guest may open
   731→   731→   `/dev/audio` 3–5 times concurrently (ringtone + media + notification). Spawn-on-accept is
   732→   732→   correct, but cap the total to avoid a thread storm.
   733→   733→5. **RECORD_AUDIO permission UX.** When the guest tries to record (e.g. for a voice message
   734→   734→   in WhatsApp), twoyi needs to prompt the user for RECORD_AUDIO at runtime. VM does this
   735→   735→   via `PermissionEvent` on EventBus; twoyi should do the same via an Activity Result API.
