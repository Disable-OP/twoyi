# LOG SOURCE MANIFEST — read BEFORE interpreting any artifact.
# Two Android systems produce logs in this run:
#   HOST  = the redroid container's own Android (its framework
#           boot is NOT twoyi progress, no matter how similar
#           it looks)
#   GUEST = the Android running inside the twoyi app
#   APP   = the twoyi app process itself (bridges GUEST data)
#
# HOST   logcat.txt                 adb logcat -d of the redroid HOST
# HOST   logcat-dockerexec.txt      host logcat via docker exec
# HOST   redroid.log                docker container log
# HOST   docker-exec-watch.log      liveness watcher; its ps lines are HOST
#                                   processes (explicitly labeled in-log)
# APP    app-logs/log/*.log         twoyi app FileLogger (app story; kr64.log
#                                   inside it carries the GUEST klog timeline)
# GUEST  kr64-app-stderr.log        kr64 daemon stderr — guest syscall traces
#                                   + KLOG-TIMELINE (the boot-timeline source)
# GUEST  dev-__kmsg__               guest __kmsg__ mirror (guest kernel-log
#                                   writes incl. init/recovery fatals)
# GUEST  property-area-state.txt    guest rootfs property area state
# GUEST  property-values.txt        strings-probe of the guest property
#                                   area CONTEXT FILES (which ro./sys./
#                                   init.svc.* values actually LANDED in
#                                   the guest area — the decisive artifact
#                                   for landed-vs-denied property sets;
#                                   6-Z305p lesson: the area LISTING alone
#                                   cannot distinguish them)
# MIXED  ps-dockerexec.txt          FULL host ps -A dump — guest processes are
#                                   the io.twoyi.debug SUBTREE only (the
#                                   classifier's guest_process_view does the
#                                   BFS; raw ps includes HOST framework procs)
#
# Rung verdicts: scripts/android-boot-classify.py consumes kr64 logs,
# property-area state, and the io.twoyi.debug ps subtree ONLY.
